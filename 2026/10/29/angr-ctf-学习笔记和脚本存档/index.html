02_angr_find_condition

上面两种情况都是可以直接找到地址的情况，但是如果在某些情况下对于目的地址不明确，就需要通过其他方法来实现了。
Angr is powerful in that it allows you to search for a states that meets an arbitrary condition that you specify in Python, using a predicate you define as a function that takes a state and returns True if you have found what you are looking for, and False otherwise.

这样的话可操作性就非常高了，例如判断是否输出了字符串、是否执行了某个功能等等。

# Define a function that checks if you have found the state you are looking
# for.
def is_successful(state):
  # Dump whatever has been printed out by the binary so far into a string.
  stdout_output = state.posix.dumps(sys.stdout.fileno())

  # Return whether 'Good Job.' has been printed yet.
  # (!)
  return 'Good Job.' in stdout_output  # :boolean

# Same as above, but this time check if the state should abort. If you return
# False, Angr will continue to step the state. In this specific challenge, the
# only time at which you will know you should abort is when the program prints
# "Try again."
# 即，如果这个函数返回 False，那么就继续往前推断。如果返回 True，那么就停止然后转到其他分支
def should_abort(state):
  stdout_output = state.posix.dumps(sys.stdout.fileno())
  return "Try again." in stdout_output  # :boolean

# Tell Angr to explore the binary and find any state that is_successful identfies
# as a successful state by returning True.
simulation.explore(find=is_successful, avoid=should_abort)

补充

最后的 solver 是什么，eval 又是什么？

solver 是 Angr 和底层约束求解引擎之间的桥梁。Angr 使用的 Claripy 默认通过 Z3 作为后端求解器。可以把 solver 理解为：挂在 Angr 的程序状态 state 上的一个“数学求解器接口”，负责根据约束计算符号变量可能的值。
https://api.angr.io/en/stable/core-concepts/solver.html

solver.eval 让求解器计算一个表达式的具体值。最常见的用途就是从符号变量中取出满足当前约束的一个具体值。
eval() 不一定是在求解一个独立的符号变量，它可以计算任何 Claripy 表达式。

        addr=start_addr,

        return b"Try again" in output

补充

不能理解，simulation.found 出现之后，不是应该已经结束执行了吗？为什么后面加一个约束还能够接着求解？还是说后面没有在求解？

程序执行到哪里了，和求解器还可以做什么，是两回事。
simulation.found 不代表程序已经运行结束，而是代表 Angr 找到了一个符合 find 条件的执行状态。之后你仍然可以修改这个状态的约束，让求解器根据新条件反推出输入。

可以把整个过程想成在程序中设置断点：

输入符号密码
    ↓
执行 complex_function 加密
    ↓
到达 check_equals 调用前  ← Angr 在这里暂停
    ↓
检查加密结果是否正确
    ↓
打印 Good Job. / Try again.

而 simulation.found 本身就是 SimulationManager 中的一个 stash（17_angr_arbitrary_jump 中会提到这个 stashes 设置）。
explore() 不只是返回一个布尔值，它会把到达目标地址的执行状态放到 found 这个 stash 中。状态里面保存了当前的寄存器、内存、符号表达式以及已经积累的约束。文档也提到，可以取出 found 中的状态，继续分析它或从中提取输入。

可以把 solution_state 想成一张程序的快照：

程序计数器：停在指定地址
内存：保存着此时的加密结果
符号变量：仍然保留着原始 password
约束：此前执行路径已经积累的条件

注意，此时 password 通常还没有被求解成一个确定的字符串。它依旧是符号变量。

假设原始密码是 $x$，加密函数是 $F$，那么执行到这里时，缓冲区保存的实际上是 $F(x)$。
而 add_constraints，本质上是在给这个快照添加一个新的数学条件 $F(x)=\texttt{AQMKNVLWBGUVQTAG}$

代码 做什么 会继续执行程序吗？
simulation.explore(...) 符号执行，搜索符合条件的状态 会，直到找到目标
solution_state.add_constraints(...) 对已找到的状态增加条件 不会
solution_state.solver.eval(password, ...) 求出满足条件的密码值 不会

后面没有继续执行程序，但确实在求解。求解器使用新加入的约束和此前的符号计算关系，反向求出一个符合要求的原始输入。

当调用 state.solver.eval() 时才真正请求求解器算出 password 的具体值。

使用修饰器语法进行 hook：

@project.hook(check_equals_called_address, length=instruction_to_skip_length)
def skip_check_equals_(state):

其中，第一个参数是要 hook 的地址，第二个参数是 hook 了这个地址之后，应该让 angr 跳过多长的程序内容。
除此之外，在该函数中还应该设置返回值，通过 state.regs.eax 可以设置。
另外，由于是在描述一个供 z3 使用的等式（而不是要立即求值），所以不能使用 Python 的 if else 语法。
必须使用 claripy 内置的、用于处理 if 语句的函数。
claripy.If(expression, ret_if_true, ret_if_false) 会输出一个表达式：如果 expression 为真，则求值为 ret_if_true，否则求值为 ret_if_false。可以把它类比成 Python 的 “value0 if expression else value1”。

state.regs.eax = claripy.If(
  user_input_string == check_against_string, 
  claripy.BVV(1, 32), 
  claripy.BVV(0, 32)
)

# 本关卡执行以下计算过程：
#
# 1. 获取 16 字节的用户输入并对其进行加密。
# 2. 保存 check_equals_AABBCCDDEEFFGGHH（或类似函数）的返回结果。
# 3. 再从用户处获取另外 16 字节并对其进行加密。
# 4. 检查该结果是否等于一个预定义的密码。
#
# 这个程序中我们唯一需要关心的部分是第 2 步。我们将使用 hook 把对
# check_equals_ 的调用替换成我们自己的版本，因为否则 check_equals_
# 运行得会太慢。

import angr
import claripy
import sys

def main(argv):
  path_to_binary = argv[1]
  project = angr.Project(path_to_binary)

  # 由于 Angr 能够处理最初对 scanf 的调用，我们可以从程序开头开始。
  initial_state = project.factory.entry_state(
    add_options = { angr.options.SYMBOL_FILL_UNCONSTRAINED_MEMORY,
                    angr.options.SYMBOL_FILL_UNCONSTRAINED_REGISTERS}
  )

  # Hook 住调用 check_equals_ 的那个地址。
  # (!)
  check_equals_called_address = 0x8049240# 0x804934e

  # angr.Hook 中的 length 参数指定：在执行完 hook 之后，
  # 执行引擎应跳过多少个字节。这样可以让 hook 替换某些指令
  # （或指令组）。确定调用 check_equals_ 所涉及的指令，
  # 然后确定它们在内存中占多少字节。这个值就是跳过长度。
  # (!)
  instruction_to_skip_length = 0x4d# 保留 ret 以便能够给 call 返回 esp     # 5
  @project.hook(check_equals_called_address, length=instruction_to_skip_length)
  def skip_check_equals_(state):
    # 确定用户输入存储的地址。该地址会作为参数传给
    # check_equals_ 函数。然后加载该字符串。提醒：
    # int check_equals_(char* to_check, int length) { ...
    user_input_buffer_address = 0x804c038 # :integer，通常是十六进制
    user_input_buffer_length = 0x10# ???

    # 提醒：state.memory.load 会从地址
    # user_input_buffer_address 处读取长度为
    # user_input_buffer_length 字节的已存储值。
    # 它会返回一个保存该值的位向量。这个值可能是符号值，
    # 也可能是具体值，取决于程序当时在那里存储了什么。
    user_input_string = state.memory.load(
      user_input_buffer_address,
      user_input_buffer_length
    )
    
    # 确定这个函数正在拿用户输入与哪个字符串进行比较。
    # 该字符串编码在这个函数的名字中；反编译程序即可找到它。
    check_against_string = "PHTDLRAYFYIVHXYF" # :string

    # 如果返回值是整数，gcc 会使用 eax 来存储它。
    # 如果 check_against_string == user_input_string，我们需要把
    # eax 设为 1，否则设为 0。
    # 不过，由于我们是在描述一个供 z3 使用的等式（而不是要立即求值），
    # 所以不能使用 Python 的 if else 语法。相反，我们必须使用
    # claripy 内置的、用于处理 if 语句的函数。
    # claripy.If(expression, ret_if_true, ret_if_false) 会输出一个
    # 表达式：如果 expression 为真，则求值为 ret_if_true，
    # 否则求值为 ret_if_false。
    # 可以把它类比成 Python 的 "value0 if expression else value1"。
    state.regs.eax = claripy.If(
      user_input_string == check_against_string, 
      claripy.BVV(1, 32),

为什么替换 call 和替换对应函数的效果一样？

可以在函数入口替换整个函数的实现，也可以在调用指令处直接模拟函数执行后的效果。只要两种做法让程序接下来看到的状态相同，就可以得到相同的结果。
Hook 并不需要真的执行函数里的每条汇编指令；它只需要模拟后续代码依赖的效果。
在某些情况下这两种方式并不通用。
第一，Hook 函数入口通常会影响所有进入该函数的调用。 而 Hook 某一条 call 指令只影响这个调用点，其他地方调用同一函数时仍然会执行原函数或其他 Hook。
第二，如果 Hook 依赖函数参数，两个位置的参数布局不同。
在函数入口，32 位 x86 的栈通常是：

esp + 0x00    返回地址
esp + 0x04    参数 1
esp + 0x08    参数 2

在 call 指令执行之前，则是：

esp + 0x00    参数 1
esp + 0x04    参数 2

如果改为读取栈上的参数，就必须根据 Hook 所在的位置调整偏移。
第三，原函数如果有重要副作用，也不能只设置 eax。 比如函数修改了全局变量、释放内存或者改变了其他寄存器，那么 Hook 也需要模拟这些行为，否则后续执行可能不同。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

假设：
    scanf0 = x        # 一个未知数，就像方程里的 x

关键：字母 x 本身没有值。它只是一个符号。

你做的事叫 eval(scanf0)，意思是：
    “帮我解出 x 等于几。”

怎么解？看当前有哪些条件。

【run 里 eval 时】
    条件列表是空的（因为 strncmp 还没跑，还没写条件）。
    你问：“x 等于几？”
    solver 说：“没有任何条件，我随便给你一个，x = 0。”
    这就是随机值。

【found 里 eval 时】
    strncmp 跑过了，条件列表里多了一条：
        x == 密码前4字节
    你问：“x 等于几？”
    solver 说：“根据条件 x == 密码前4字节，x = 那个密码。”
    这就是正确答案。

所以“怎么把 scanf0 拿出来”：
    你不是从 x 里“读”出一个值，x 里没值。
    你是问 solver 要一个解，solver 看当时的条件，算出答案给你。

    条件什么时候加？strncmp 跑的时候。
    run 在 strncmp 之前跑，所以 run 里问 solver，条件还没加，答案随机。
    found 在 strncmp 之后，条件加完了，答案正确。

二、对应到 angr
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 核心概念
   - scanf0 = claripy.BVS('scanf0', 32) 是一个“未知数”，本身没有值。
   - 它类似数学方程里的 x，只是一个符号。
   - 它没有“值”可以取出来，只能让 solver 根据当前约束解出一个候选值。

2. eval 是什么
   - state.solver.eval(scanf0) 的意思是：
     “在当前所有约束下，帮我解出 scanf0 可以是几。”
   - 约束不同，eval 出来的结果就不同。
   - eval 不会预知以后才加的约束，它只看调用那一刻已有的约束。

3. 程序执行顺序（一条路径）
   scanf(...)        ← run 在这里执行
   strncmp(...)      ← 约束在这里才被 add 进去
   if (...)          ← 这里才判断成功/失败并分叉

   关键：
   - run 是 scanf 的替身，执行位置就在 scanf 那一行。
   - run 执行时，strncmp 还没跑，约束还没建立。
   - 所以 run 里 eval(scanf0) 是在“空约束”下求解，得到随机值。

4. 为什么不能在 run 里先 eval 再存 globals
   错误写法：
     self.state.globals['solution0'] = (
         self.state.solver.eval(scanf0),
         self.state.solver.eval(scanf1)
     )
   问题：
   - eval 返回的是 Python int，是一个死值。
   - 这个 int 和 BVS scanf0 从此没有关系。
   - 后面 strncmp 再加约束，也改不了这个 int。
   - found 时取出来还是那个早产的随机值。

5. 正确写法
   run 里：存 BVS 本身，不要 eval
     self.state.globals['solution0'] = (scanf0, scanf1)

   found 里：用 found state 的完整约束再 eval
     stored = solution_state.globals['solution0']
     solution0 = solution_state.solver.eval(stored[0])
     solution1 = solution_state.solver.eval(stored[1])

6. 为什么 globals 能带出 run 的局部变量
   - scanf0 是 run 的局部变量，run 返回后就没了。
   - 必须存到 state 上，才能被外面的 found 代码拿到。
   - self.state.globals 是挂在 state 上的字典，会随 state 分叉一起复制。
   - 存 BVS 到 globals，相当于把“未知数”带到最后，而不是把“早产答案”带到最后。

7. 有没有“跑到 Try again 再从头跑”
   - 没有。
   - 程序执行到 if 处分叉，只走 Try again 或 Good Job 其中一条。
   - angr 的 explore(find, avoid) 是在分叉点同时探索两条路。
   - scanf、strncmp、if 分叉是顺序执行的。
   - run 在 if 分叉之前就已经执行完了。

8. 一句话总结
   - BVS 是未知数，不是值。

补充

<bitvector_name>.chop(bits=n)：每 n 位切为一个片段，返回一个 python 列表；

state.solver.symbolic(expr)：用来检查一个表达式（位向量）是否含有符号变量，返回 True 或 False。如果这个指针是由用户输入（或自行创建的 bitvector 符号变量）计算得来的，那么 puts_parameter 中就会包含符号位，symbolic 返回 True，说明这个指针“可能受用户控制”。如果它只是一个固定地址（比如函数、常量、.rodata 的地址），symbolic 会返回 False。

state.satisfiable(extra_constraints=(xx_expression,))：用来检查当前状态的所有约束加上你额外提供的约束之后，是否还存在至少一组解，能让所有约束同时成立。https://docs.angr.io/_/downloads/en/v9.2.123/pdf/#5#181#5
state.satisfiable(extra_constraints=(is_vulnerable_expression,)) 试探性地问一句：“如果我加上这个条件，还有解吗？”只有返回 True，才说明这条路可行，再用 state.add_constraints() 把它永久加入，并返回 True 让 explore 在这里停下。

#
# scanf("%d %20s", &key, user_input);
# ...
#   // if certain unknown conditions are true...
#   strncpy(random_buffer, user_input);
# ...
# if (strncmp(secure_buffer, reference_string)) {
#   // The secure_buffer does not equal the reference string.
#   puts("Try again.");
# } else {
#   // The two are equal.
#   puts("Good Job.");
# }
#
# If this program has no bugs in it, it would _always_ print "Try again." since
# user_input copies into random_buffer, not secure_buffer.
#
# The question is: can we find a buffer overflow that will allow us to overwrite
# the random_buffer pointer to point to secure_buffer? (Spoiler: we can, but we
# will need to use Angr.)
#
# We want to identify a place in the binary, when strncpy is called, when we can:
#  1) Control the source contents (not the source pointer!)
#     * This will allow us to write arbitrary data to the destination.
#  2) Control the destination pointer
#     * This will allow us to write to an arbitrary location.
# If we can meet both of those requirements, we can write arbitrary data to an
# arbitrary location. Finally, we need to contrain the source contents to be
# equal to the reference_string and the destination pointer to be equal to the
# secure_buffer.

      self.state.memory.store(scanf1_address, scanf1)

    #  esp + 2 -> |     return     |
    #  esp + 1 -> |     address    |

    strncpy_src = state.memory.load(state.regs.esp + 8, 4, endness=project.arch.memory_endness)
    strncpy_len = state.memory.load(state.regs.esp + 0xc, 4, endness=project.arch.memory_endness)

    # contents, rather than the pointer itself. Therefore, we have to load the
    # the contents of src to determine if they are symbolic.

    # (arbitrary data) and the destination pointer is symbolic (arbitrary

      # the address of the buffer it checks the password against. Our goal is to
      # overwrite that buffer to store the password.
      # (!)

      buffer_address = 0x55554b44 # :integer, probably in hexadecimal

      # while typical Python slices (array[start:end]) will work with bitvectors,
      # they are indexed in an odd way. The ranges must start with a high value
      # and end with a low value. Additionally, the bits are indexed from right
      # to left. For example, let a bitvector, b, equal 'ABCDEFGH', (64 bits).
      # The following will read bit 0-7 (total of 1 byte) from the right-most
      # bit (the end of the string).
      #  b[7:0] == 'H'
      # To access the beginning of the string, we need to access the last 16
      # bits, or bits 48-63:
      #  b[63:48] == 'AB'
      # In this specific case, since we don't necessarily know the length of the
      # contents (unless you look at the binary), we can use the following:
      #  b[-1:-16] == 'AB', since, in Python, -1 is the end of the list, and -16
      # is the 16th element from the end of the list. The actual numbers should
      # correspond with the length of password_string.

# An unconstrained state occurs when there are too many
# possible branches from a single instruction. This occurs, among other ways,
# when the instruction pointer (on x86, eip) is completely symbolic, meaning
# that user input can control the address of code the computer executes.
# For example, imagine the following pseudo assembly:
#
# mov user_input, eax
# jmp eax
#
# The value of what the user entered dictates the next instruction. This
# is an unconstrained state. It wouldn't usually make sense for the execution
# engine to continue. (Where should the program jump to if eax could be
# anything?) Normally, when Angr encounters an unconstrained state, it throws
# it out. In our case, we want to exploit the unconstrained state to jump to
# a location of our choosing. We will get to how to disable Angr's default
# behavior later.
#
# This challenge represents a classic stack-based buffer overflow attack to
# overwrite the return address and jump to a function that prints "Good Job."
# Our strategy for solving the challenge is as follows:
# 1. Initialize the simulation and ask Angr to record unconstrained states.
# 2. Step through the simulation until we have found a state where eip is
#    symbolic.
# 3. Constrain eip to equal the address of the "print_good" function.

import angr
import claripy
import sys

import traceback

def check_errors(simulation):
  print('====================')
  print("Simulation:", simulation)
  print("Stashes:", {
    name: len(states)
    for name, states in simulation.stashes.items()
  })
  print("Errored:", len(simulation.errored))

  for record in simulation.errored:
    print("Error:", record.error)
    print("State address:", record.state.addr)

    traceback.print_exception(
        type(record.error),
        record.error,
        record.traceback,
    )
  print('====================')

def main(argv):
  path_to_binary = argv[1]
  project = angr.Project(path_to_binary)

  # Make a symbolic input that has a decent size to trigger overflow
  # (!)
  symbolic_input = claripy.BVS("input", (0x21 + 4 + 4) * 8)
  # symbolic_input = claripy.BVS("input", 0x80 * 8)# 理论上来说瞎写一个数值也可以？不行，SimPacketsStream 不接受这么大的数值

  # Create initial state and set stdin to the symbolic input
  # 以下 stdin 传参修改
  # https://github.com/angr/angr-doc/blob/master/docs/file_system.md
  # https://api.angr.io/en/v9.2.112/advanced-topics/file_system.html
  # 把符号位向量直接作为 stdin 传入时，Angr 会用普通的扁平 SimFile 来保存它，而不是适合模拟输入流的 SimPackets。
  # scanf 的 %s 处理逻辑会搜索输入中的分隔符。这个搜索过程尝试将不同位宽的地址表达式合并，最终触发了 Claripy 的位宽检查异常 “args' length must all be equal”
  scanf_stdin = angr.SimPacketsStream(
    name='scanf_stdin', 
    content=[symbolic_input], 
    write_mode=False, 
  )
  initial_state = project.factory.entry_state(
          # stdin=symbolic_input,
          stdin = scanf_stdin,
          add_options = {
              angr.options.SYMBOL_FILL_UNCONSTRAINED_MEMORY,
              angr.options.SYMBOL_FILL_UNCONSTRAINED_REGISTERS
              }
          )

  # The save_unconstrained=True parameter specifies to Angr to not throw out
  # unconstrained states. Instead, it will move them to the list called
  # 'simulation.unconstrained'.  Additionally, we will be using a few stashes
  # that are not included by default, such as 'found' and 'not_needed'. You will
  # see how these are used later.
  # (!)
  simulation = project.factory.simgr(
    initial_state,
    save_unconstrained=True, # ???,
    # stashes={
      # 'active' : [initial_state, ],# 正在运行的
      # 'unconstrained' : [],# 未约束的 eip 状态？
      # 'found' : [],
      # 'not_needed' : []
    # }
  )
  simulation.stashes['found'] = []# 让 Angr 初始化默认的 active、deadended、unconstrained 等 stash

  # Explore will not work for us, since the method specified with the 'find'
  # parameter will not be called on an unconstrained state. Instead, we want to
  # explore the binary ourselves. To get started, construct an exit condition
  # to know when the simulation has found a solution. We will later move
  # states from the unconstrained list to the simulation.found list.
  # Create a boolean value that indicates a state has been found.
  def has_found_solution():
    return simulation.found

  # An unconstrained state occurs when there are too many possible branches
  # from a single instruction. This occurs, among other ways, when the
  # instruction pointer (on x86, eip) is completely symbolic, meaning
  # that user input can control the address of code the computer executes.
  # For example, imagine the following pseudo assembly:
  #
  # mov user_input, eax
  # jmp eax
  #
  # The value of what the user entered dictates the next instruction. This
  # is an unconstrained state. It wouldn't usually make sense for the execution
  # engine to continue. (Where should the program jump to if eax could be
  # anything?) Normally, when Angr encounters an unconstrained state, it throws
  # it out. In our case, we want to exploit the unconstrained state to jump to
  # a location of our choosing.  Check if there are still unconstrained states
  # by examining the simulation.unconstrained list.
  # (!)
  def has_unconstrained_to_check():
    return simulation.unconstrained

  # The list simulation.active is a list of all states that can be explored
  # further.
  # (!)
  def has_active():
    return simulation.active

  while (has_active() or has_unconstrained_to_check()) and (not has_found_solution()):
    for unconstrained_state in simulation.unconstrained:
        # Look for unconstrained states and move them to the 'found' stash.
        # A 'stash' should be a string that corresponds to a list that stores
        # all the states that the state group keeps. Values include:
        #  'active' = states that can be stepped
        #  'deadended' = states that have exited the program
        #  'errored' = states that encountered an error with Angr
        #  'unconstrained' = states that are unconstrained
        #  'found' = solutions
        #  anything else = whatever you want, perhaps you want a 'not_needed',
        #                  you can call it whatever you want
        # (!)
      simulation.move('unconstrained', 'found')

    # Advance the simulation.
    simulation.step()

  # ====================
  # check_errors(simulation)
  # ====================


  if simulation.found:
    solution_state = simulation.found[0]

    # Constrain the instruction pointer to target the print_good function and
    # (!)
    solution_state.add_constraints(solution_state.regs.eip == 0x5a514854)

    # Constrain the symbolic input to fall within printable range (capital
    # letters) for the web UI.  Ensure UTF-8 encoding.
    # (!)
    for byte in symbolic_input.chop(bits=8):
      solution_state.add_constraints(
              byte >= ord('A'),
              byte <= ord('Z')
      )

    # Solve for the symbolic_input
    solution = solution_state.solver.eval(symbolic_input,cast_to=bytes).decode()
    print(solution)
  else:
    # 以下排查代码问题用
    print("active:", len(simulation.active))
    print("unconstrained:", len(simulation.unconstrained))
    print("found:", len(simulation.found))
    print("deadended:", len(simulation.deadended))
    print("errored:", len(simulation.errored))
    if len(simulation.errored) != 0:
      for error in simulation.errored:
        print(type(error.error).__name__, error.error)
    raise Exception('Could not find the solution')

if __name__ == '__main__':
  main(sys.argv)
