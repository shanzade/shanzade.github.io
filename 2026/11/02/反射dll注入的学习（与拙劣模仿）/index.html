https://github.com/stephenfewer/ReflectiveDLLInjection

step. 0

不要用 debug 方案
不要开优化
不要开地址随机
不要开预编译

整个顺序：

外部 loader：读文件 → 找导出函数的文件偏移 → 调用 ReflectiveLoader

ReflectiveLoader：找自己的基址 → 找所需 API → 分配新映像
                 → 拷贝头和节区 → 修正导入 → 修正重定位
                 → 刷新指令缓存 → 调用入口点

loader

注意加上 VirtualAlloc 返回的地址。
注意函数代码和导出表可能在不同的节区，不能用导出表所在节的换算结果去换算函数地址。

不要和 LoadLibraryA() 相提并论。前者得到的已经是内存布局，而直接通过 CreateFile + ReadFile + VirtualAlloc 读进来的是文件布局。

注意 vs 不会自动对应到 dll 所在位置（如果是手动读的话）

step. 1

解析当前 dll 所在的地址（包括 PE 头等）

注意检查 MZ 头和 PE 头。单独遇到 MZ 两个字节不能说明已经找到头了，也可能只是指令或者数据刚好一样。

倒着找，是因为这里 ret_addr() 返回到加载器代码里面，而代码位于文件头之后。
e_lfanew 是相对于文件开头的偏移，不是已经加好基址的地址；这里加上 uiLibraryAddress 才能读 nt 头。

e_lfanew <= 0x1000 是这个示例用的筛选条件，不是所有 PE 文件都必须满足的格式要求。这个倒扫本身也没有完整的可读内存边界检查。

#include <intrin.h>

#pragma intrinsic(_ReturnAddress)
__declspec(noinline) ULONG_PTR WINAPI ret_addr(void) {
    return (ULONG_PTR)_ReturnAddress();
}
// ==================== 解析当前 dll 所在的地址（包括 pe 头等） ====================
uiLibraryAddress = ret_addr();
for (;;) {
    // 不断往回遍历映像头（因为 .text 段必定是在整个映像里面，所以说往低地址遍历就能找到）
    // （此处的 IMAGE_DOS_SIGNATURE 是 Windows.h 的？）
    if (((PIMAGE_DOS_HEADER)uiLibraryAddress)->e_magic == IMAGE_DOS_SIGNATURE) {
        // 如果找到了 MZ，就表明找到了开头；
        // stephen 的例子里面提到检查 x64 指令的问题（POP R10）
        // 因为后面要加上基址，很有可能会内存越界，所以说不检查应该是不行的。
        uiPEHeader = ((PIMAGE_DOS_HEADER)uiLibraryAddress)->e_lfanew;
        if (uiPEHeader >= sizeof(IMAGE_DOS_HEADER) && uiPEHeader <= 0x1000) {
            // 到了这一步，说明 uiLibraryAddresss 指向的有概率是 0 偏移位置
            uiPEHeader += uiLibraryAddress;
            if (((PIMAGE_NT_HEADERS)uiPEHeader)->Signature == IMAGE_NT_SIGNATURE) {
                // 此时确定；
                break;
            }
        }
    }
    uiLibraryAddress--;
}

ReturnAddress

#include <intrin.h>。

_ReturnAddress 是一个 MSVC 内建函数，它映射到一条 MOV RAX, [RSP]（x64）或 MOV EAX, [ESP]（x86）这类指令——读取当前栈顶的返回地址。
这里就是 ReflectiveLoader 调用 ret_addr() 后面的位置，因此能拿到加载器自身附近的地址。

__declspec(noinline) 是为了保留这层函数调用。如果被内联，_ReturnAddress() 的含义就变成外层函数的返回地址，而不是“调用 caller 之后那条指令”的地址。

链表头和模块结点

InMemoryOrderModuleList 是循环链表，结尾不会自动变成 NULL。
头结点只是 LIST_ENTRY，不能当成一个实际模块去读 BaseDllName。

所以先保存头结点地址，遍历到头结点就停。不能利用 Buffer 是否为空来判断头结点，因为在此处的代码读这个字段时已经默认结点不为空。

Flink 指向下一个模块内部的 InMemoryOrderLinks，不一定是整个 LDR_DATA_TABLE_ENTRY 的开头，所以要用 CONTAINING_RECORD 找回结构体地址。

导出表的几层索引

AddressOfNames            → DWORD 数组，每项是函数名的 RVA
AddressOfNameOrdinals     → WORD 数组，每项是函数地址表的索引
AddressOfFunctions        → DWORD 数组，每项是导出地址的 RVA

名字数组下标 i
    → ordinals[i]
    → functions[ordinals[i]]
    → 加模块基址得到地址

注意 AddressOfNameOrdinals 指向的数组元素是索引，不是 rva，也不是已经加上 Base 的公开导出序号。数组字段本身才是 rva。

有些 AddressOfFunctions 项指向的是转发字符串，不是可执行代码；如果 rva 落在导出目录范围内，就要按转发信息继续解析，不能直接调用。此处暂时不考虑这个了

rotr 和 hash

#pragma intrinsic(_rotr) 告诉编译器使用内建实现，针对 _rotr 进行优化，循环右移通常能生成对应的硬件指令。
__forceinline 要求尽量内联，但不是绝对。

hash_wchar 名字虽然带 wchar，实际是把 utf16le 字符串当字节序列计算，不是真的每次处理一个 wchar_t。
c++ 移动指针不能忘记

#define HASH_KEY 0XD

#pragma intrinsic( _rotr)
__forceinline DWORD ror(DWORD dwD) {
    return _rotr(dwD, HASH_KEY);
}
__forceinline DWORD hash(char* c) {
    register DWORD hash = 0;// 将变量尽可能放到寄存器上
    do {
        hash = ror(hash);
        hash += *c;
    } while (*(++c));
    return hash;
}
__forceinline DWORD hash_wchar(char* c, size_t len) {
    register DWORD hash = 0;// 将变量尽可能放到寄存器上
    for (size_t i = 0; i < len; ++i) {
        hash = ror(hash);
        if (*c >= 'a') {
            hash += (*c - 0x20);
        }
        else {
            hash += *c;
        }
        c++;
    }
    return hash;
}

Length 和 MaximumLength

字段 含义

MaximumLength 缓冲区容量，单位也是字节

step. 3

根据 SizeOfImage 分配新映像，再拷贝 PE 头

分配用 SizeOfImage，拷贝头用 SizeOfHeaders，不是把文件缓冲区按 SizeOfImage 直接读一遍。

还有无符号数这个坑：ULONG_PTR 永远不会小于 0。while (--uiVal1 >= 0) 会在零之后下溢，继续越界。

uiVal1 = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.SizeOfHeaders;
while (uiVal1 != 0) {
    --uiVal1;
    // 拷贝内容

step. 4

根据 sections RVA 拷贝到对应位置

定位节表可以通过 &OptionalHeader + SizeOfOptionalHeader。

源地址 = 原始文件基址 + PointerToRawData
目标地址 = 新映像基址 + VirtualAddress
拷贝长度 = SizeOfRawData

VirtualAlloc 新分配的内存初始为零，所以节区中只有虚拟大小、没有文件数据的部分保留为零；当前代码仍假定节表和原始数据范围是有效的。

// 根据 sections rva 拷贝到对应位置
uiVal1 = (ULONG_PTR) & ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader + ((PIMAGE_NT_HEADERS)uiPEHeader)->FileHeader.SizeOfOptionalHeader;
dwCount = ((PIMAGE_NT_HEADERS)uiPEHeader)->FileHeader.NumberOfSections;
while (dwCount--) {
    uiVal2 = ((PIMAGE_SECTION_HEADER)uiVal1)->VirtualAddress + uiAddressNew;// 新映像中的目标地址
    uiVal3 = ((PIMAGE_SECTION_HEADER)uiVal1)->PointerToRawData + uiLibraryAddress;// 拿到文件地址
    auto dwCount2 = ((PIMAGE_SECTION_HEADER)uiVal1)->SizeOfRawData;// 拿到文件中节区大小
    // 拷贝
    while (dwCount2--)
        *(BYTE*)uiVal2++ = *(BYTE*)uiVal3++;

    uiVal1 += sizeof(IMAGE_SECTION_HEADER);// 下一个节区
}

step. 5

遍历并处理导入表

导入目录是一组 IMAGE_IMPORT_DESCRIPTOR，最后一个描述符全为零。

OriginalFirstThunk 指向 INT，FirstThunk 指向 IAT。未修正时两边通常保存相同的内容（IMAGE_IMPORT_BY_NAME 数组），修正后 IAT 里面是实际函数地址。
如果 OriginalFirstThunk == 0，就用 FirstThunk 作为查找表

一些小问题

这里绕了很久，即：

// 注意下面这里的 AddressOfData 是自己的 dll 里面的，而不是导进来的 dll
uiVal3 = uiAddressNew + ((PIMAGE_THUNK_DATA)uiVal1)->u1.AddressOfData;

虽然在找 LoadLibrary 加载进来的 dll 的函数，但是 AddressOfData 对应的函数名还在自己的 dll 里面。
即，要区分自己的导入表和 dll 的导出表。

ai 概括：
比如当前 dll 导入 user32.dll!MessageBoxA：

自己的新映像（uiAddressNew）
    导入描述符 → "user32.dll"
    INT 条目 → IMAGE_IMPORT_BY_NAME → "MessageBoxA"
    IAT 条目 ← 最后写入实际函数地址

依赖 dll（uiLibraryAddress2）
    user32.dll 的导出信息 → MessageBoxA 的实际地址

从新映像读取“我要导入谁”，去依赖 dll 查“函数在哪里”，再把结果写回新映像的 IAT。

// 自己的新映像里找函数名
uiVal3 = uiAddressNew +
    ((PIMAGE_THUNK_DATA)uiVal1)->u1.AddressOfData;

// 去依赖 dll 查实际地址
uiVal4 = (ULONG_PTR)pfGetProcAddress(
    (HMODULE)uiLibraryAddress2,
    (LPCSTR)((PIMAGE_IMPORT_BY_NAME)uiVal3)->Name
);

// 写回自己的 IAT
*(UINT_PTR*)uiVal2 = uiVal4;

如果按序号导入，最高位标记用于区分类型，取出实际序号之后减去导出表的 Base，才是函数地址表索引。这个序号和前面名称导出表里的 AddressOfNameOrdinals 索引不要混了。

step. 6

处理重定位表

delta = 实际基址（VirtualAlloc 返回的） - ImageBase;

重定向地址里默认是自动加上 ImageBase 的。
不是一定把所有字段都加一遍 delta / 只修改重定位表列出的那些位置里保存的绝对地址值。

// 处理重定位表
// 首先要知道 ImageBase，重定位条目记录需要修正的位置，那些位置保存的绝对地址需要加偏移。
uiAddress = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_BASERELOC].VirtualAddress;
dwCount = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_BASERELOC].Size;
uiVal1 = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.ImageBase;
uiVal2 = uiAddressNew - uiVal1;// delta;
// 判断是否需要重定位
if (uiVal2 != 0) {
    // 不存在重定位需求则结束
    if (uiAddress == 0 || dwCount == 0) {
        return 0;
    }
    uiAddress += uiAddressNew;
    while (dwCount >= sizeof(IMAGE_BASE_RELOCATION)) {
        auto block = (PIMAGE_BASE_RELOCATION)uiAddress;
        // 块大小不能小于块头，也不能超出目录剩余范围
        if (block->SizeOfBlock < sizeof(IMAGE_BASE_RELOCATION)
            || block->SizeOfBlock > dwCount) {
            return 0;
        }

        DWORD entriesSize = block->SizeOfBlock - sizeof(IMAGE_BASE_RELOCATION);
        // 必须是整数倍
        if (entriesSize % sizeof(WORD) != 0) {
            return 0;
        }

        DWORD entryCount = entriesSize / sizeof(WORD);

        // 每个重定位条目紧跟在重定位块头之后
        WORD* entry = (WORD*)(uiAddress + sizeof(IMAGE_BASE_RELOCATION));

        // 遍历当前块中的每个重定位条目
        for (DWORD i = 0; i < entryCount; ++i) {
            UCHAR ucType = entry[i] >> 12;
            WORD usOffset = entry[i] & 0x0fff;
            // 填充条目，不需要修改
            if (ucType == IMAGE_REL_BASED_ABSOLUTE) {
                continue;
            }
            // 暂时只支持 x64 的 64 位地址重定位
            if (ucType != IMAGE_REL_BASED_DIR64) {

        dwCount -= block->SizeOfBlock;


    }
    if (dwCount != 0) {
        return 0;
    }
}

重定位表补充

重定位目录包含多个块。每个块先是一个 IMAGE_BASE_RELOCATION，然后紧跟若干 WORD 条目：

一个块：
    VirtualAddress   DWORD  4 字节：这一块对应的页面 RVA
    SizeOfBlock      DWORD  4 字节：整个块占的字节数
    条目 0           WORD   2 字节
    条目 1           WORD   2 字节
    ……

SizeOfBlock 包括 8 字节块头，也包括后面的所有条目和填充条目。
不是页面大小，也不是整个重定位目录的大小。

条目数 = (SizeOfBlock - sizeof(IMAGE_BASE_RELOCATION)) / sizeof(WORD);
下一块地址 = 当前块地址 + SizeOfBlock;

每个 WORD 的高 4 位是类型，低 12 位是页内偏移：

UCHAR type = entry[i] >> 12;
WORD offset = entry[i] & 0x0fff;

当前只支持 x64：IMAGE_REL_BASED_DIR64 修正 8 字节地址；IMAGE_REL_BASED_ABSOLUTE 是填充，跳过。其他类型返回失败。

target = 新基址 + block->VirtualAddress + 页内偏移
*target += delta

target 是要修改的位置，*target 才是里面保存的地址值。
比如 0xA038，A 表示 DIR64，038 是页内偏移；页面 RVA 为 0x3000 时，修改新映像偏移 0x3038 处的 8 字节。

// 管理进程句柄：打开之后由析构函数自动 CloseHandle。
class Proc {
    HANDLE hProc = nullptr;
public:
    Proc() = default;
    // 禁止复制，否则两个对象会持有同一个句柄，并在析构时重复关闭。
    Proc(const Proc&) = delete;
    Proc& operator=(const Proc&) = delete;
    bool OpenProcessByPid(DWORD pid) {
        if (hProc) CloseHandle(hProc);
        // 查询权限用于 VirtualQueryEx；读取权限用于 ReadProcessMemory。
        hProc = OpenProcess(PROCESS_QUERY_INFORMATION | PROCESS_VM_READ, FALSE, pid);
        return hProc != nullptr;
    }
    HANDLE getHandle() const { return hProc; }
    ~Proc() { if (hProc) CloseHandle(hProc); }
};

// 第一层：已提交 + 私有 + 可执行，就是本原型需要列出的候选区域。
// MEM_PRIVATE 不是“恶意”的意思，JIT 等正常程序也可能申请这种内存。
bool IsCandidate(const MEMORY_BASIC_INFORMATION& mbi) {
    if (mbi.State != MEM_COMMIT || mbi.Type != MEM_PRIVATE ||
        (mbi.Protect & PAGE_GUARD)) return false;
    // 低 8 位是基础权限；PAGE_GUARD 等修饰标志单独判断。
    // 保护页不主动读取，避免干扰目标进程的保护页行为。
    switch (mbi.Protect & 0xFF) {
    case PAGE_EXECUTE:
    case PAGE_EXECUTE_READ:
    case PAGE_EXECUTE_READWRITE:
    case PAGE_EXECUTE_WRITECOPY:
        return true;
    default: return false;
    }
}

// 头部标签：读不到 / 没有 MZ / 只有 MZ / 同时有 MZ 和 PE 签名。
// 有签名也不代表完整有效的 DLL，这里没有继续解析节表等结构。
enum class PeTag { Unreadable, NoSignature, MzOnly, PeSignature };

// T 由传入的对象自动推导：传 dos 就读取 sizeof(IMAGE_DOS_HEADER) 字节，
// 传 DWORD 就读取 4 字节。value 是引用，读取结果会写回调用者的变量。
template<typename T>
bool ReadValue(HANDLE process, ULONG_PTR address, T& value) {
    // address 属于目标进程，不能在 Detector 里直接 *(T*)address。
    // 必须先复制到本进程的 value。下面先确保最后一个字节的地址不会溢出。
    if (address > std::numeric_limits<ULONG_PTR>::max() - (sizeof(T) - 1)) return false;
    // API 成功和实际读满都要满足，部分读取不能当作完整结构体使用。
    SIZE_T read = 0;
    return ReadProcessMemory(process, (LPCVOID)address, &value,
                             sizeof(value), &read) && read == sizeof(value);
}

// 第二层：在原始分配的开头找 MZ，再到 e_lfanew 指定的位置找 PE\0\0。
// 用提前 return 处理失败，避免把每个检查都套成一层 if。
PeTag CheckPeSignature(HANDLE process, ULONG_PTR allocationBase) {
    MEMORY_BASIC_INFORMATION headerRegion{};
    if (VirtualQueryEx(process, (LPCVOID)allocationBase, &headerRegion,
                       sizeof(headerRegion)) != sizeof(headerRegion) ||
        headerRegion.State != MEM_COMMIT ||
        (headerRegion.Protect & (PAGE_GUARD | PAGE_NOACCESS)))
        return PeTag::Unreadable;
    // 即使候选代码区域可执行，分配开头的头部也可能不可读，先独立检查。
    IMAGE_DOS_HEADER dos{};
    if (!ReadValue(process, allocationBase, dos)) return PeTag::Unreadable;
    if (dos.e_magic != IMAGE_DOS_SIGNATURE) return PeTag::NoSignature;
    // e_lfanew 是相对于分配开头的偏移。1 MiB 是原型限制，不是 PE 格式要求。
    if (dos.e_lfanew < static_cast<LONG>(sizeof(dos)) || dos.e_lfanew > 0x100000)
        return PeTag::MzOnly;
    // 前面排除了负数，再转成能保存指针的无符号整数，准备与基址相加。
    ULONG_PTR offset = static_cast<ULONG_PTR>(dos.e_lfanew);
    if (allocationBase > std::numeric_limits<ULONG_PTR>::max() - offset)
        return PeTag::MzOnly;
    ULONG_PTR ntAddress = allocationBase + offset;
    MEMORY_BASIC_INFORMATION region{};
    // 偏移可能是伪造的，不能误把另一块分配里的字节当作当前 PE 的签名。
    if (VirtualQueryEx(process, (LPCVOID)ntAddress, &region, sizeof(region)) != sizeof(region) ||
        (ULONG_PTR)region.AllocationBase != allocationBase ||
        region.State != MEM_COMMIT || (region.Protect & PAGE_GUARD)) return PeTag::MzOnly;
    // 确认 4 字节签名完整落在查询到的区域内，再交给 ReadProcessMemory 读取。
    SIZE_T regionOffset = ntAddress - (ULONG_PTR)region.BaseAddress;
    if (regionOffset > region.RegionSize || region.RegionSize - regionOffset < sizeof(DWORD))
        return PeTag::MzOnly;
    DWORD signature = 0;
    if (!ReadValue(process, ntAddress, signature)) return PeTag::Unreadable;
    return signature == IMAGE_NT_SIGNATURE ? PeTag::PeSignature : PeTag::MzOnly;
}

// 把内部枚举转换成用于打印的文字；不在检查函数里到处打印。
const char* TagName(PeTag tag) {
    switch (tag) {
    case PeTag::PeSignature: return "MZ+PE signatures (not fully validated)";
    case PeTag::MzOnly: return "MZ only / no readable PE signature";
    case PeTag::NoSignature: return "no MZ signature";
    default: return "header unreadable";
    }
}

struct ScanResult {
    SIZE_T regions = 0;       // 符合条件的区域数
    SIZE_T allocations = 0;   // 这些区域归属的不同分配数
    SIZE_T peAllocations = 0; // 分配开头含 MZ + PE 签名的数量
    // 查询中途失败时不能把不完整结果说成“扫描完成”。
    bool complete = true;
};

ScanResult ScanProcess(HANDLE process) {
    ScanResult result;
    // key 是 AllocationBase，value 是该分配的头部检查结果。
    // 一次 VirtualAlloc 可能因权限不同而分成多个区域，所以缓存检查结果。
    std::map<ULONG_PTR, PeTag> allocations;
    SYSTEM_INFO system{};
    GetNativeSystemInfo(&system);
    // 得到当前系统的用户态地址上限，逐区域查询，不逐字节扫描。
    ULONG_PTR maxAddress = (ULONG_PTR)system.lpMaximumApplicationAddress;
    ULONG_PTR address = 0;
    while (address <= maxAddress) {
        MEMORY_BASIC_INFORMATION mbi{};
        if (VirtualQueryEx(process, (LPCVOID)address, &mbi, sizeof(mbi)) != sizeof(mbi)) {
            DWORD error = GetLastError();
            std::fprintf(stderr, "VirtualQueryEx failed at %p: error %lu. Scan incomplete.\n",
                         (void*)address, error);
            result.complete = false;
            break;
        }
        // BaseAddress 是当前属性一致的区域；AllocationBase 是原始分配开头。
        // 一个分配可能有多个区域，但每一个候选区域仍要输出自己的权限和大小。
        if (IsCandidate(mbi)) {
            ++result.regions;
            ULONG_PTR allocationBase = (ULONG_PTR)mbi.AllocationBase;
            // find 返回迭代器；等于 end() 表示这个分配还没检查过。
            auto found = allocations.find(allocationBase);
            bool firstRegion = found == allocations.end();
            if (firstRegion) {
                PeTag tag = CheckPeSignature(process, allocationBase);
                // emplace 插入“基址 → 标签”，返回值的 first 是该项的迭代器。
                found = allocations.emplace(allocationBase, tag).first;
                ++result.allocations;
                if (tag == PeTag::PeSignature) ++result.peAllocations;
            }
            // 没有 PE 头、头部不可读，也照样输出候选；不能因此漏掉 shellcode。
            std::printf("[Private executable] Region=%p Allocation=%p Size=0x%llX Protect=0x%lX\n",
                mbi.BaseAddress, mbi.AllocationBase,
                static_cast<unsigned long long>(mbi.RegionSize), mbi.Protect);
            // 迭代器的 first 是基址，second 是标签。
            if (firstRegion) std::printf("  Allocation header: %s\n", TagName(found->second));
            else std::printf("  Same allocation as an earlier region.\n");
        }
        // 下一次查询 = 当前区域起点 + 区域大小，不是 AllocationBase + RegionSize。
        // 无论是否命中候选都必须前进，因此不能在上面随便 continue。
        ULONG_PTR base = (ULONG_PTR)mbi.BaseAddress;
        if (mbi.RegionSize > std::numeric_limits<ULONG_PTR>::max() - base) break;
        ULONG_PTR next = base + mbi.RegionSize;
        if (next <= address) {
            std::fprintf(stderr, "Memory query did not advance. Scan incomplete.\n");
            result.complete = false;
            break;
        }
        address = next;
    }
    std::printf("\n%s: %llu candidate regions, %llu unique allocations, "
                "%llu allocations with MZ+PE signatures.\n",
        result.complete ? "Scan finished" : "Partial scan",
        static_cast<unsigned long long>(result.regions),
        static_cast<unsigned long long>(result.allocations),
        static_cast<unsigned long long>(result.peAllocations));
    std::printf("Candidates need investigation; JIT and other legitimate code can also match.\n");
    return result;
}

// 输入检查独立出来，让 main 只保留“获取 PID → 打开进程 → 扫描”的主线。
bool ParsePid(const std::string& text, DWORD& pid) {
    if (text.empty() || text.find_first_not_of("0123456789") != std::string::npos) return false;
    // strtoul 将十进制字符串转换成整数；errno/末尾位置用于确认没有溢出或残留字符。
    errno = 0;
    char* end = nullptr;
    unsigned long value = std::strtoul(text.c_str(), &end, 10);
    if (errno == ERANGE || *end != '\0' || value == 0 ||
        value > std::numeric_limits<DWORD>::max()) return false;
    pid = static_cast<DWORD>(value);
    return true;
}

    Proc process;
    if (!process.OpenProcessByPid(pid)) {
        DWORD error = GetLastError();
        std::fprintf(stderr, "OpenProcess(%lu) failed: error %lu.\n", pid, error);
        return 1;
    }
    std::printf("Scanning PID %lu...\n", pid);
    // 退出码：0 扫描完成；1 输入或打开失败；2 扫描中途失败。
    // 是否发现候选区域不影响退出码，查看输出里的统计即可。
    return ScanProcess(process.getHandle()).complete ? 0 : 2;
}

// 不要对 _ReturnAddress 进行内联。
#pragma intrinsic(_ReturnAddress)
__declspec(noinline) ULONG_PTR WINAPI ret_addr(void) { return (ULONG_PTR)_ReturnAddress(); }

ULONG_PTR WINAPI ReflectiveLoader()
{
    // --- 一些函数指针 ---
    MYLOADLIBRARYA pfLoadLibraryA = NULL;
    MYGETPROCADDRESS pfGetProcAddress = NULL;
    MYVIRTUALALLOC pfVirtualAlloc = NULL;
    MYNTFLUSHINSTRUCTIONCACHE pfNtFlushInstructionCache = NULL;

    // --- 一些变量 ---
    LONG dwCount;
    USHORT usFlag;

    ULONG_PTR uiLibraryAddress, uiLibraryAddress2;// 存放映像基址
    ULONG_PTR uiPEHeader;// PE 头地址（非 rva）
    ULONG_PTR uiAddress;// 存放各种地址
    ULONG_PTR uiAddressNew;// 新的 rwx

    ULONG_PTR uiModuleLinkAddress;
    ULONG_PTR uiBufferAddress;
    ULONG_PTR uiHashResult;

    ULONG_PTR uiVal1;
    ULONG_PTR uiVal2;
    ULONG_PTR uiVal3;
    ULONG_PTR uiVal4;

    // ==================== 解析当前 dll 所在的地址（包括 pe 头等） ====================
    uiLibraryAddress = ret_addr();
    for (;;) {
        // 不断往回遍历映像头（因为 .text 段必定是在整个映像里面，所以说往低地址遍历就能找到）
        // （此处的 IMAGE_DOS_SIGNATURE 是 Windows.h 的？）
        if (((PIMAGE_DOS_HEADER)uiLibraryAddress)->e_magic == IMAGE_DOS_SIGNATURE) {
            // 如果找到了 MZ，就表明找到了开头；
            // stephen 的例子里面提到检查 x64 指令的问题（POP R10）
            // 因为后面要加上基址，很有可能会内存越界，所以说不检查应该是不行的。
            uiPEHeader = ((PIMAGE_DOS_HEADER)uiLibraryAddress)->e_lfanew;
            if (uiPEHeader >= sizeof(IMAGE_DOS_HEADER) && uiPEHeader <= 0x1000) {
                // 到了这一步，说明 uiLibraryAddresss 指向的有概率是 0 偏移位置
                uiPEHeader += uiLibraryAddress;
                if (((PIMAGE_NT_HEADERS)uiPEHeader)->Signature == IMAGE_NT_SIGNATURE) {
                    // 此时确定；
                    break;
                }
            }
        }
        uiLibraryAddress--;
    }
    
    // ==================== 解析宿主进程的 peb，找到所需的三个函数 LoadLibraryA、GetProcAddress、VirtualAlloc ====================
#ifdef WIN_X86
    uiAddress = __readfsdword(0x30); // x86 peb
#else
//#ifdef WIN_X64
    // 暂不讨论 windows on arm 的问题
    uiAddress = __readgsqword(0x60);// x64 peb
#endif
    uiAddress = (ULONG_PTR)(((PPEB)uiAddress)->Ldr);// 解析 ldr

    ULONG_PTR listHead = (ULONG_PTR)&((PPEB_LDR_DATA)uiAddress)->InMemoryOrderModuleList;
    uiModuleLinkAddress = *(ULONG_PTR*)listHead;
    while (uiModuleLinkAddress != 0 && uiModuleLinkAddress != listHead) {
        // 进入一个结点（_LDR_DATA_TABLE_ENTRY）
        // 要注意偏移问题！
        uiAddress = (ULONG_PTR)CONTAINING_RECORD(uiModuleLinkAddress, LDR_DATA_TABLE_ENTRY, InMemoryOrderLinks);
        // 放到前面来判断是否为空结点
        uiBufferAddress = (ULONG_PTR)((PLDR_DATA_TABLE_ENTRY)uiAddress)->BaseDllName.Buffer;
        if (uiAddress && uiBufferAddress) {
            // 开始判断 BaseDllName
            dwCount = ((PLDR_DATA_TABLE_ENTRY)uiAddress)->BaseDllName.MaximumLength;
            //uiBufferAddress = (ULONG_PTR)((PLDR_DATA_TABLE_ENTRY)uiAddress)->BaseDllName.Buffer;
            uiHashResult = hash_wchar((char*)uiBufferAddress, dwCount);

            // 如果成立的话，应该在里面找到导出表，遍历导出函数名和 Ordinals，然后找到对应的函数
            if (uiHashResult == KERNEL32DLL_HASH) {
                usFlag = 0;

                uiAddress = (ULONG_PTR)((PLDR_DATA_TABLE_ENTRY)uiAddress)->DllBase;// 拿到 DllBase
                uiVal1 = (ULONG_PTR)((PIMAGE_DOS_HEADER)uiAddress)->e_lfanew;// 找到 pe 头（注意是个 rva）
                // 拿到导出表位置

                uiVal1 = (ULONG_PTR)((PIMAGE_NT_HEADERS)uiVal1)->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_EXPORT].VirtualAddress;

                    if (uiVal4 == LOADLIBRARYA_HASH) {
                        uiVal4 = ((PIMAGE_EXPORT_DIRECTORY)uiVal1)->AddressOfFunctions;

                        pfLoadLibraryA = (MYLOADLIBRARYA)(((DWORD*)uiVal4)[((USHORT*)uiVal3)[dwCount]] + uiAddress);// 这里也要 + 基址
                        ++usFlag;
                        //break;
                    }
                    else if (uiVal4 == GETPROCADDRESS_HASH) {
                        uiVal4 = ((PIMAGE_EXPORT_DIRECTORY)uiVal1)->AddressOfFunctions;
                        uiVal4 += uiAddress;
                        pfGetProcAddress = (MYGETPROCADDRESS)(((DWORD*)uiVal4)[((USHORT*)uiVal3)[dwCount]] + uiAddress);
                        ++usFlag;
                        //break;
                    } 
                    else if (uiVal4 == VIRTUALALLOC_HASH) {
                        uiVal4 = ((PIMAGE_EXPORT_DIRECTORY)uiVal1)->AddressOfFunctions;
                        uiVal4 += uiAddress;
                        pfVirtualAlloc = (MYVIRTUALALLOC)(((DWORD*)uiVal4)[((USHORT*)uiVal3)[dwCount]] + uiAddress);
                        ++usFlag;
                        //break;
                    }
                }
            }
            else if (uiHashResult == NTDLLDLL_HASH) {
                //MessageBoxA(NULL, "ntdll", "a", MB_ICONWARNING|MB_OK);
                uiAddress = (ULONG_PTR)((PLDR_DATA_TABLE_ENTRY)uiAddress)->DllBase;// 拿到 DllBase
                uiVal1 = (ULONG_PTR)((PIMAGE_DOS_HEADER)uiAddress)->e_lfanew;// 找到 pe 头（注意是个 rva）

                    if (uiVal4 == NTFLUSHINSTRUCTIONCACHE_HASH) {
                        uiVal4 = ((PIMAGE_EXPORT_DIRECTORY)uiVal1)->AddressOfFunctions;
                        uiVal4 += uiAddress;
                        pfNtFlushInstructionCache = (MYNTFLUSHINSTRUCTIONCACHE)(((DWORD*)uiVal4)[((USHORT*)uiVal3)[dwCount]] + uiAddress);// 这里也要 + 基址
                        break;
                    }
                }
            }
        }

        if (pfLoadLibraryA != NULL
            && pfGetProcAddress != NULL
            && pfVirtualAlloc != NULL
            && pfNtFlushInstructionCache != NULL) {
            break;
        }

        // 因为 InMemoryOrderLinks 会指向下一个结点对应的 InMemoryOrderLinks 位置，所以不用加偏移。
        uiModuleLinkAddress = *(ULONG_PTR *)(uiModuleLinkAddress);

    }

    // 遍历完成后仍未找齐函数，不能继续调用空函数指针。
    if (!pfLoadLibraryA || !pfGetProcAddress ||
        !pfVirtualAlloc || !pfNtFlushInstructionCache) {
        return 0;
    }

    // 根据 SizeOfImage 创建新的位置
    uiVal1 = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.SizeOfImage;

    while (dwCount--) {

        uiVal3 = ((PIMAGE_SECTION_HEADER)uiVal1)->PointerToRawData + uiLibraryAddress;// 拿到文件地址
        auto dwCount2 = ((PIMAGE_SECTION_HEADER)uiVal1)->SizeOfRawData;// 拿到文件中节区大小
        // 拷贝
        while (dwCount2--)
            *(BYTE*)uiVal2++ = *(BYTE*)uiVal3++;

        uiVal1 += sizeof(IMAGE_SECTION_HEADER);// 下一个节区
    }

    // 处理导入表
    uiAddress = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_IMPORT].VirtualAddress;
    uiAddress += uiAddressNew;
    // 应该如何遍历？
    // 在所有结构的最后, 由一个内容全为0的IMAGE_IMPORT_DESCRIPTOR结构作为结束标志
    // 通过 OriginalFirstThunk 可以找到 INT，通过 FirstThunk 可以找到 IAT
    // 最开始二者指向同一个东西，当 pe 被载入内存之后，FirstThunk 就会被修正为指针数组，jmp dword ptr [xxx] 就是这么来的
    while (((PIMAGE_IMPORT_DESCRIPTOR)uiAddress)->Name) {
        // 如果内容为空，说明已经是最后一个导入表了，这时候应该退出循环

        // 先加载对应 dll，然后根据 Ordinals 或者 Names 进行函数的查找
        uiLibraryAddress2 = (ULONG_PTR)pfLoadLibraryA( (LPCSTR) (uiAddressNew + ((PIMAGE_IMPORT_DESCRIPTOR)uiAddress)->Name)  );

        uiVal1 = ((PIMAGE_IMPORT_DESCRIPTOR)uiAddress)->OriginalFirstThunk;// INT
        uiVal2 = ((PIMAGE_IMPORT_DESCRIPTOR)uiAddress)->FirstThunk;// IAT
        if (uiVal1 == 0) {
            uiVal1 = uiVal2;
        }
        uiVal1 += uiAddressNew; uiVal2 += uiAddressNew;

        while (*(ULONG_PTR*)uiVal2) {// 这里也需要解引用；要区分地址和内容
            // 如果是编号，则手动解析
            if (uiVal1 && ((PIMAGE_THUNK_DATA)uiVal1)->u1.Ordinal & IMAGE_ORDINAL_FLAG) {
                // 找目标 dll 的导出表
                uiVal3 = uiLibraryAddress2 + ((PIMAGE_DOS_HEADER)uiLibraryAddress2)->e_lfanew;
                uiVal3 = uiLibraryAddress2 + ((PIMAGE_NT_HEADERS)uiVal3)->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_EXPORT].VirtualAddress;

                uiVal4 = uiLibraryAddress2 + ((PIMAGE_EXPORT_DIRECTORY)uiVal3)->AddressOfFunctions;
                dwCount = ((PIMAGE_EXPORT_DIRECTORY)uiVal3)->Base;// 导出序号的起始数值
                // 因为存放在导入表中的内容是加上了 Base 起始序号的，所以如果要找到对应 Ordinal 的函数，
                // 则需要减去 Base
                // 要记得索引！
                uiVal4 += ((IMAGE_ORDINAL(((PIMAGE_THUNK_DATA)uiVal1)->u1.Ordinal) - dwCount) * sizeof(DWORD));
                *(UINT_PTR*)uiVal2 = uiLibraryAddress2 + *(DWORD*)uiVal4;// 这里要记得解引用，因为 uiVal4 是一个地址，指向存放 rva 的内容
            }
            // 否则就是直接通过 GetProcAddress 导入
            else {
                // 注意下面这里的 AddressOfData 是自己的 dll 里面的，而不是导进来的 dll
                uiVal3 = uiAddressNew + ((PIMAGE_THUNK_DATA)uiVal1)->u1.AddressOfData;
                uiVal4 = (ULONG_PTR)pfGetProcAddress((HMODULE)uiLibraryAddress2, (LPCSTR)((PIMAGE_IMPORT_BY_NAME)uiVal3)->Name);
                *(UINT_PTR*)uiVal2 = uiVal4;
            }

            // （结束位置是一个空的 rva）
            uiVal2 += sizeof(ULONG_PTR);
            if (uiVal1) {
                uiVal1 += sizeof(ULONG_PTR);
            }
        }

        uiAddress += sizeof(IMAGE_IMPORT_DESCRIPTOR);// 下一个导入表
    }

    // 处理重定位表
    // 首先要知道 ImageBase，重定位条目记录需要修正的位置，那些位置保存的绝对地址需要加偏移。
    uiAddress = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_BASERELOC].VirtualAddress;
    dwCount = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_BASERELOC].Size;
    uiVal1 = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.ImageBase;
    uiVal2 = uiAddressNew - uiVal1;// delta;
    // 判断是否需要重定位
    if (uiVal2 != 0) {
        // 不存在重定位需求则结束
        if (uiAddress == 0 || dwCount == 0) {
            return 0;
        }
        uiAddress += uiAddressNew;
        while (dwCount >= sizeof(IMAGE_BASE_RELOCATION)) {
            auto block = (PIMAGE_BASE_RELOCATION)uiAddress;
            // 块大小不能小于块头，也不能超出目录剩余范围
            if (block->SizeOfBlock < sizeof(IMAGE_BASE_RELOCATION)
                || block->SizeOfBlock > dwCount) {
                return 0;
            }

            DWORD entriesSize = block->SizeOfBlock - sizeof(IMAGE_BASE_RELOCATION);
            // 必须是整数倍
            if (entriesSize % sizeof(WORD) != 0) {
                return 0;
            }

            DWORD entryCount = entriesSize / sizeof(WORD);

            // 每个重定位条目紧跟在重定位块头之后
            WORD* entry = (WORD*)(uiAddress + sizeof(IMAGE_BASE_RELOCATION));

            // 遍历当前块中的每个重定位条目
            for (DWORD i = 0; i < entryCount; ++i) {
                UCHAR ucType = entry[i] >> 12;
                WORD usOffset = entry[i] & 0x0fff;
                // 填充条目，不需要修改
                if (ucType == IMAGE_REL_BASED_ABSOLUTE) {
                    continue;
                }
                // 暂时只支持 x64 的 64 位地址重定位
                if (ucType != IMAGE_REL_BASED_DIR64) {
                    return 0;
                }
                ULONG_PTR targetRva = (ULONG_PTR)block->VirtualAddress + usOffset;
                // 确认目标位置的完整 8 字节都在映像范围内
                if (targetRva > ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.SizeOfImage 
                    || ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.SizeOfImage - targetRva < sizeof(ULONG_PTR)) {
                    return 0;
                }

                // 修改目标位置的重定位
                ULONG_PTR target = uiAddressNew + targetRva;
                *(ULONG_PTR*)target += uiVal2;
            }

            // 移动到下一个重定位块
            uiAddress += block->SizeOfBlock;
            dwCount -= block->SizeOfBlock;


        }
        if (dwCount != 0) {
            return 0;
        }
    }

    // 调用入口点
    uiVal1 = ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.AddressOfEntryPoint;
    if (uiVal1 == 0) {
        return 0;
    }
    uiVal1 += uiAddressNew;
    // 刷新缓存，-1 表示当前进程
    pfNtFlushInstructionCache((HANDLE) - 1, (PVOID)uiAddressNew, ((PIMAGE_NT_HEADERS)uiPEHeader)->OptionalHeader.SizeOfImage);
    if (!((BOOL(WINAPI *)(HMODULE, DWORD, LPVOID))uiVal1)(
        (HINSTANCE)uiAddressNew, 
        DLL_PROCESS_ATTACH, 
        NULL)) {
        return 0;// 失败
    }

    // 返回入口点
    return uiVal1;
}
